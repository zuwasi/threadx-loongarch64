# DEV-010: Compile-time checks use the unused-typedef static assertion idiom

| Field | Value |
|---|---|
| Deviation ID | DEV-010 |
| Guideline | Rule 2.3 (Advisory): A project should not contain unused type declarations |
| Parasoft checkers | MISRAC2025-RULE_2_3-b |
| Status | Draft (approval pending) |
| Scope | Port |
| Requirement(s) | LA-REQ-001, LA-REQ-003, LA-REQ-005, LA-REQ-006 |

## 1. Locations

| File | Function or symbol |
|---|---|
| `ports/loongarch64/gnu/src/tx_la64_port_assert.c` | `tx_la64_thread_run_count_offset_check`, `tx_la64_thread_stack_ptr_offset_check`, `tx_la64_thread_stack_end_offset_check`, `tx_la64_thread_time_slice_offset_check`, `tx_la64_context_alignment_check` |

The same idiom appears once in `tx_port.h`
(`tx_la64_pointer_width_check`); the checker has not reported it there.

## 2. Reason for the deviation

The port verifies its C/assembly ABI assumptions at compile time. The
project language is ISO C99 without GNU extensions (GEP 7), so
`_Static_assert` (C11) is not available; the typedef-of-array idiom is the
only C99 construct that fails compilation when a condition is false. The
typedefs are intentionally unused - their negative array size is the
assertion.

## 3. Risk analysis

- **Hazard:** an unused declaration may be dead code that hides a real
  mistake.
- **Why it cannot occur here:** each typedef is the check itself; if the
  asserted condition fails, the array size becomes negative and the build
  stops. The deviation cannot hide a broken ABI - it is the mechanism that
  detects it.

## 4. Compensating measures

- The asserted offsets implement LA-REQ-001/003/005/006; a failed check is a
  compile error, and CI builds every configuration.
