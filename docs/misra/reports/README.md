# MISRA C:2025 analysis reports

| | |
|---|---|
| Project | Eclipse ThreadX port for LoongArch64 (ESL) |
| Standard | MISRA C:2025, compliance per MISRA Compliance:2020 |
| Tool | Parasoft C/C++test Standard 2026.1.3, configuration `tools/parasoft/ESL_MISRA_C_2025.properties` (rule map `MISRAC2025.xml` 9.5.0) |
| Cross compiler | GCC 14.2.0 `loongarch64-linux-gnu`, analysed through the custom compiler definition (`tools/parasoft/make_compiler_def.sh`) |
| Plan | [Guideline Enforcement Plan](../gep.md); the Guideline Compliance Summary is [guideline-compliance-summary.md](guideline-compliance-summary.md) |

## Contents

- `product/` - **Compliance scope.**  The `threadx` library (ThreadX kernel
  sources plus the LoongArch64 port) and the `bsp_qemu_virt` library,
  Release build; test code is not built (GEP scope table).  The compliance
  summary evaluates only `ports/loongarch64/` and `bsp/`.  Findings under
  `external/threadx/` in this report are the input to the separate kernel
  gap analysis (M7) and carry no compliance claim.  Current result
  (2026-10-21, UART RX route, LA-REQ-105): 0 findings in the port and the
  BSP, including `bsp/qemu_virt/src/intr.c`; all 613 findings are in
  `external/threadx/common`.
- `tests/` - **Test-harness scope, reported separately.**  Bring-up, demo
  and the regression harness build (default configuration), which also
  compiles the port with `TX_REGRESSION_TEST` defined.  ESL-written test
  code is `test/bringup/`, `test/threadx_demo/` and
  `test/regression/libc/`; anything else in this report is upstream
  (kernel or upstream test sources).

  Current result (2026-10-22, 1.0.0-rc1 tree, including the LA-REQ-001
  data-model check in `bringup_main.c`): no findings in `ports/`, `bsp/`,
  `test/bringup/` or `test/threadx_demo/`.  The 90 findings in
  `test/regression/libc/` follow from its purpose: it implements the C
  library calls the upstream suite makes (`printf` with `<stdarg.h>`,
  `puts`, `exit`, `time`, `rand`) under their reserved names and standard
  signatures (Rules 5.10, 17.1, 21.6, 21.10, Dir 4.6).  The harness is
  never part of a delivered image, so these are recorded, not deviated.

- [ThreadX common kernel gap analysis](../kernel-gap-analysis.md) - report-only
  summary of the 613 MISRA C:2025 findings under `external/threadx/common/`.
  It makes no compliance claim and does not modify the submodule.

Both reports were generated by the commands below; the HTML and SARIF files
are the Parasoft outputs, unmodified.

## Regenerating

```sh
tools/misra.sh product build/misra          # -> build/misra/report
tools/misra.sh tests   build/misra-tests    # -> build/misra-tests/report
tools/parasoft/validate.sh                  # -> build/tool-validation/report
tools/parasoft/gcs_gen.py build/misra/report/report.sarif \
    > docs/misra/reports/guideline-compliance-summary.md
```

`CPPTEST_HOME` and `CPPTEST_SETTINGS` (the license settings file, kept
outside the repository) must be set; see `tools/misra.sh`.

## Suppressions in the source

Every `parasoft-suppress` comment in the sources names the deviation
record that justifies it (`DEV-nnn`, see [../deviations/](../deviations/));
the Guideline Compliance Summary lists them per guideline.
