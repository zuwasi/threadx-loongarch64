# DEV-015: Tick counter reads in bring-up tests reported as unchecked returns

| Field | Value |
|---|---|
| Deviation ID | DEV-015 |
| Guideline | Dir 4.7 (Required): If a function returns error information, then that error information shall be tested |
| Parasoft checkers | MISRAC2025-DIR_4_7-a |
| Status | Draft (approval pending) |
| Scope | Two locations |
| Requirement(s) | LA-REQ-011, LA-REQ-105 |

## 1. Locations

| File | Symbol |
|---|---|
| `test/bringup/bringup_long_idle.c` | `idle_test_entry`, the elapsed-tick report after the idle interval |
| `test/bringup/bringup_uart_rx.c` | `rx_test_entry`, the receive-window tick accounting |

## 2. Reason for the deviation

`tx_time_get` returns the current system tick counter.  Its return value is
a measurement, not error information, so the obligation of Dir 4.7 to test
returned error information does not engage for this call.  The checker
applies a scope-wide consistency heuristic: it reports calls whose results
are not used in a controlling condition when at least 80% of the calls to
the same method in the analysis scope are used that way.  In the testing
scope most `_tx_time_get` calls sit in `while`-conditions, so the calls
that only take a measurement are reported.

## 3. Risk analysis

- **Hazard addressed by the guideline:** proceeding after a failed call
  because the returned error status was ignored.
- **Why it cannot occur here:**
  - The function cannot fail: the ThreadX API returns the tick count on
    every call; there is no error status that could be ignored.
  - Both measured values are consumed by the tests: the long-idle test
    derives `elapsed_ticks` and its pass verdict requires
    `elapsed_ticks >= IDLE_TEST_TICKS`; the UART receive test bounds its
    wait with `(tx_time_get() - start_tick) < RX_WAIT_TICKS` (a call used
    in a controlling condition, not reported) and prints the window length
    as run evidence.
  - Adding a controlling condition on the raw tick reads would restate
    arithmetic already covered by the tests' verdicts.
- **Evidence:** the same tick path is exercised by the six-configuration
  regression suite (96/96 tests in each) through `tx_thread_sleep`.

## 4. Compensating measures

- The pass verdict of each affected test depends on the measured timing:
  the long-idle verdict requires the elapsed tick count to reach the
  requested sleep, and the UART receive verdict requires the full payload
  to arrive within the bounded wait window.
