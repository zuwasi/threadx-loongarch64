# DEV-013: ThreadX version ID declared without a product-scope definition

| Field | Value |
|---|---|
| Deviation ID | DEV-013 |
| Guideline | Rule 8.6 (Required): An identifier with external linkage shall have exactly one external definition; Rule 2.8 (Advisory): A project should not contain unused object definitions |
| Parasoft checkers | MISRAC2025-RULE_8_6-b, MISRAC2025-RULE_2_8-a |
| Status | Draft (approval pending) |
| Scope | Single location |
| Requirement(s) | LA-REQ-001 |

## 1. Locations

| File | Function or symbol |
|---|---|
| `ports/loongarch64/gnu/inc/tx_port.h` | `extern CHAR _tx_version_id[160];` |

## 2. Reason for the deviation

The ThreadX porting interface exposes the version string through
`_tx_version_id`: every upstream port declares it, and the upstream
regression suite prints it (`testcontrol.c`, which defines `TX_THREAD_INIT`
before including `tx_api.h` and therefore owns the single definition).
In the product build no translation unit defines `TX_THREAD_INIT` and
nothing references the object; removing the declaration would break the
upstream harness, which cannot be modified.

## 3. Risk analysis

- **Hazard addressed by Rule 8.6:** an externally declared object without a
  definition can bind to an unexpected definition or fail to link.
- **Why it cannot occur here:** in the product scope there is no reference
  to the object (this is what the Rule 2.8 finding itself demonstrates), so
  nothing can bind at link time and no code path can touch it. In the
  regression scope the object has exactly one definition, in the harness
  translation unit, and the suite links and passes.
- **Evidence:** the regression suite prints the version string on every run
  and passes 96/96 in six configurations; the release build links cleanly
  with a map file showing no unresolved symbols.
- **Rule 2.8 (Advisory):** the declaration is interface documentation
  required by the porting convention, not dead code; no storage is
  allocated for an extern declaration.

## 4. Compensating measures

- The declaration and the `TX_THREAD_INIT` definition both state the array
  size explicitly (160), so an accidental mismatch cannot occur.
- The map file review per release covers the symbol.
