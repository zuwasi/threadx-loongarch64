# DEV-004: ThreadX extension hooks are function-like macros

| Field | Value |
|---|---|
| Deviation ID | DEV-004 |
| Guideline | Dir 4.9 (Advisory): A function should be used in preference to a function-like macro where they are interchangeable |
| Parasoft checkers | MISRAC2025-DIR_4_9-a |
| Status | Draft (approval pending) |
| Scope | Project-wide (port) |
| Requirement(s) | LA-REQ-001 |

## 1. Locations

| File | Function or symbol |
|---|---|
| `ports/loongarch64/gnu/inc/tx_port.h` | `TX_THREAD_CREATE_TIMEOUT_SETUP`, `TX_THREAD_TIMEOUT_POINTER_SETUP`, `TX_THREAD_*_EXTENSION` object hooks (18), `TX_TIMER_INITIALIZE_EXTENSION` |

## 2. Reason for the deviation

The ThreadX kernel invokes all of these as function-like macros inside its
own sources (for example `TX_THREAD_CREATE_EXTENSION(thread_ptr)` in
`tx_thread_create.c`). The port may only *define* them; replacing them with
functions would require modifying `external/threadx`, which is out of scope.
They are not interchangeable with functions, so the guideline does not apply
in its intent.

## 3. Risk analysis

- **Hazard addressed by the guideline:** function-like macros hide type
  checking and can evaluate arguments more than once.
- **Why it cannot occur here:** 19 of the 21 macros are empty or (in
  regression builds) expand to guarded statements on a single simple
  argument; the two timeout-setup macros operate on the caller's own thread
  pointer with interrupts disabled, in the kernel's critical section. The
  regression suite runs the timeout and expiration paths on QEMU in six
  configurations (M4 evidence).

## 4. Compensating measures

- The macros are defined in one place, `tx_port.h`, and reviewed with the
  port (M3 review records).
- The regression suite exercises the timeout-setup macros (every thread
  create) and the timer initialize hook.
