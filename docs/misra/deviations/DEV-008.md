# DEV-008: ISO C signatures use `int` for `memset` and `memcmp`

| Field | Value |
|---|---|
| Deviation ID | DEV-008 |
| Guideline | Dir 4.6 (Advisory): typedefs that indicate size and signedness should be used in place of the basic integer types |
| Parasoft checkers | MISRAC2025-DIR_4_6-b |
| Status | Draft (approval pending) |
| Scope | Port libc |
| Requirement(s) | LA-REQ-010 |

## 1. Locations

| File | Function or symbol |
|---|---|
| `ports/loongarch64/gnu/libc/include/string.h` | parameters of `memset`, return of `memcmp` |
| `ports/loongarch64/gnu/libc/src/tx_la64_string.c` | `memset` parameter, `memcmp` return value and its byte comparison |

## 2. Reason for the deviation

`memset(void *s, int c, size_t n)` and `int memcmp(...)` are the ISO C99
(7.21) signatures. The port libc must match them exactly, because GCC
assumes the built-in semantics of these functions in a freestanding
environment (DEV-001, reason). A size-tagged type would change the required
signature.

## 3. Risk analysis

- **Hazard:** a basic type whose width differs from the caller's expectation
  would corrupt data.
- **Why it cannot occur here:** `int` is exactly 32 bits on the pinned
  toolchain (LA64, LP64D); the `memset` value is explicitly masked to 8 bits
  before use, and `memcmp` converts both bytes through the same type before
  subtracting, so no width assumption is violated. Unit tests are planned in
  M6 for all four functions (DEV-001 evidence).

## 4. Compensating measures

- The `nm -u` audit (DEV-001) confirms no second definition of the functions.
- M6 unit tests cover the value handling, including `memset` values above
  255.
