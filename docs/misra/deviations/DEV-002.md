# DEV-002: ThreadX internal identifiers use the reserved `_tx_` prefix

| Field | Value |
|---|---|
| Deviation ID | DEV-002 |
| Guideline | Rule 5.10 (Required): A reserved identifier or reserved macro name shall not be declared |
| Parasoft checkers | MISRAC2025-RULE_5_10-a |
| Status | Draft (approval pending) |
| Scope | Project-wide (port) |
| Requirement(s) | LA-REQ-002, LA-REQ-102, LA-REQ-103 |

## 1. Locations

| File | Function or symbol |
|---|---|
| `ports/loongarch64/gnu/inc/tx_port.h` | declaration of `_tx_thread_interrupt_control`, prototype of `_tx_timer_interrupt` |
| `ports/loongarch64/gnu/src/tx_timer_interrupt.c` | definition of `_tx_timer_interrupt` |
| `ports/loongarch64/gnu/inc/tx_port.h` | declaration and definition of `_tx_version_id` |

The suppression comments in the sources carry this record's ID at every
location the checker reports; the published scan
(`docs/misra/reports/product/`) lists the instances.

## 2. Reason for the deviation

The `_tx_` prefix on internal ThreadX symbols is fixed by the ThreadX
porting interface: the kernel calls `_tx_thread_interrupt_control`
(`txe_thread_interrupt_control.c`) and the exception vector assembly jumps
to `_tx_timer_interrupt`. The names cannot be changed without modifying
`external/threadx`, which the project does not do (GEP scope).

## 3. Risk analysis

- **Hazard addressed by the guideline:** identifiers beginning with an
  underscore are reserved for the implementation at file scope. If the
  implementation used the same name, the declaration would collide with it,
  giving undefined behaviour.
- **Why it cannot occur here:** the toolchain is fixed and pinned
  (GCC 14.2.0 `loongarch64-linux-gnu`, binutils from Ubuntu 24.04,
  `docs/safety/tools.md` 3.1). The compiler's own symbols and its runtime
  libraries contain no `_tx_` names. Any collision would surface as a
  multiple-definition or unresolved-symbol error at link time
  (`-nostdlib`, `-Wl,--build-id=none`, no shared libraries), not as a
  silent run-time failure.
- **Evidence:** clean link of every executable with `-Werror`; one link map
  per target (`-Wl,-Map=`); the convention is the same in the ThreadX
  kernel and every upstream port.

## 4. Compensating measures

- CI links every target with `-nostdlib`; duplicate or unresolved symbols
  fail the build.
- The `nm -u` audit of DEV-001 additionally guards the port libc, where
  interposition with implementation-provided functions would be possible.
