# DEV-003: ThreadX API basic types use the names fixed by `tx_api.h`

| Field | Value |
|---|---|
| Deviation ID | DEV-003 |
| Guideline | Dir 4.6 (Advisory): typedefs that indicate size and signedness should be used in place of the basic integer types |
| Parasoft checkers | MISRAC2025-DIR_4_6-a, MISRAC2025-DIR_4_6-c |
| Status | Draft (approval pending) |
| Scope | Project-wide (port) |
| Requirement(s) | LA-REQ-001 |

## 1. Locations

| File | Function or symbol |
|---|---|
| `ports/loongarch64/gnu/inc/tx_port.h` | `UCHAR`, `INT`, `UINT`, `LONG`, `ULONG`, `ULONG64`, `SHORT`, `USHORT`, `ALIGN_TYPE`, `TEST_FLAG` (regression block) |

## 2. Reason for the deviation

`UCHAR` to `ULONG`, `ULONG64`, `SHORT`, `USHORT` and `ALIGN_TYPE` are the
ThreadX API types: every declaration in `tx_api.h` and all kernel sources use
them, and the ThreadX porting interface requires the port to define them.
Renaming them to size-tagged names would modify `external/threadx`.
`TEST_FLAG` is the type the upstream regression suite uses for its test
control flags.

## 3. Risk analysis

- **Hazard addressed by the guideline:** a basic-type typedef without a size
  in its name can silently change width between platforms, corrupting
  kernel control blocks.
- **Why it cannot occur here:** the sizes are pinned and checked
  statically: `tx_la64_port_assert.c` verifies the offsets of the ThreadX
  control block fields (`__builtin_offsetof`), and `tx_port.h` contains a
  compile-time check that pointers are 64 bits. The kernel would fail to
  link or to run its regression suite if any width changed.

## 4. Compensating measures

- The static assertions above run on every build (a failed check is a
  compile error).
- LA-REQ-001 is verified by analysis and tests (requirements.md, A/T).
