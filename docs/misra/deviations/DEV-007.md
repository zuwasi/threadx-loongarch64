# DEV-007: MMIO device addresses are converted from integer constants

| Field | Value |
|---|---|
| Deviation ID | DEV-007 |
| Guideline | Rule 11.4 (Required): A conversion shall not be performed between a pointer to object and an arithmetic type |
| Parasoft checkers | MISRAC2025-RULE_11_4-b |
| Status | Draft (approval pending) |
| Scope | BSP only |
| Requirement(s) | LA-REQ-104, LA-REQ-107 |

## 1. Locations

| File | Function or symbol |
|---|---|
| `bsp/qemu_virt/src/uart.c` | `uart_reg()` - NS16550 UART 0 register window |
| `bsp/qemu_virt/src/power.c` | `bsp_poweroff()` - ACPI GED sleep control register |

## 2. Reason for the deviation

The BSP is freestanding code on a fixed platform (QEMU `virt` machine).
Memory-mapped device registers can only be named by converting their
physical addresses to pointers; the C standard provides no other mechanism.
`board.h` documents the addresses and states how they were verified.

## 3. Risk analysis

- **Hazard addressed by the guideline:** converting an integer to a pointer
  can create a misaligned, non-dereferenceable or wrong pointer.
- **Why it cannot occur here:** the two addresses are fixed platform
  constants verified against QEMU 8.2.2 (`-M virt -cpu la464`,
  `bsp/qemu_virt/inc/board.h`). Both conversions produce byte-aligned
  `volatile uint8_t *` pointers; the only further arithmetic is the addition
  of small fixed register offsets (0-5) to the UART base. The GED register
  is written once with a fixed value.
- **Evidence:** every QEMU test run exercises both conversions: the console
  output (LA-REQ-104) is the observation channel of every test, and the GED
  poweroff write (LA-REQ-107) is how every test terminates. The bring-up and
  regression suites pass 96/96 in six configurations on these paths.

## 4. Compensating measures

- The address constants live in one place (`board.h`) with their
  verification record.
- A real-hardware run is planned after release 1.0 to confirm the platform
  assumptions (`docs/safety/tools.md` 3.3).
