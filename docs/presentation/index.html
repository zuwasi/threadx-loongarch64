LoongArch looks like MIPS and is not MIPS

LoongArch borrows classic RISC idioms and even some MIPS-like semantics, but every instruction is re-encoded and the two ISAs cannot interoperate. A MIPS port would not even assemble.

Why IEC 61508, and why systematic capability 3

1
The device's market is industrialLoongson SoCs go into industrial control, energy, rail and infrastructure. Those sectors are governed by IEC 61508 or by its sector standards: IEC 61511 (process), EN 50716/EN 50128 (rail), IEC 62061 and ISO 13849 (machinery), IEC 61513 (nuclear).
2
IEC 61508 is the mother standardIt is application-independent, so it fits a reusable RTOS element that has no vehicle or plant context. ISO 26262 itself is the automotive adaptation of IEC 61508.
3
Route 1S for the port, compliant item for reuseThe port and BSP are developed to IEC 61508-3 (route 1S). The integrator gets a safety manual (IEC 61508-3 Annex D) with the assumptions of use, which is exactly what a safety element out of context needs.
4
SC 3, not SC 4SIL 3 is the highest level that is normally achieved by a single-channel software element without diverse redundancy, and it is the rigor that automotive teams know as ASIL D. SIL 4 is rare outside rail and nuclear and is usually reached with diversity at system level.
SILHigh demand / continuous: PFH (per hour)Low demand: PFDavg
SIL 410-9 to < 10-810-5 to < 10-4
SIL 310-8 to < 10-710-4 to < 10-3
SIL 210-7 to < 10-610-3 to < 10-2
SIL 110-6 to < 10-510-2 to < 10-1

Software has no failure rate. For software, a SIL is reached as a systematic capability (SC): the techniques and measures of IEC 61508-3 Annexes A and B, applied at the rigor the tables mark HR (highly recommended) for that SIL. That is why the project is "SC 3 process", not "a SIL 3 number".

tx_port.h: data model and interrupt lockout

ports/loongarch64/gnu/inc/tx_port.h (excerpt)
/* LONG and ULONG are 32-bit, as on every other ThreadX 64-bit port.  The
   kernel control-block layouts and queue message sizes depend on it.  Use
   ULONG64 for 64-bit quantities.  */
typedef int                 LONG;   /* parasoft-suppress MISRAC2025-DIR_4_6-a "DEV-003" */
typedef unsigned int        ULONG;  /* parasoft-suppress MISRAC2025-DIR_4_6-a "DEV-003" */
typedef unsigned long long  ULONG64;
typedef unsigned long long  ALIGN_TYPE;
typedef char tx_la64_pointer_width_check[(sizeof(VOID *) == 8U) ? 1 : -1];

/* ULONG is 32-bit but pointers are 64-bit, so the thread pointer for a
   timeout is kept in a pointer-sized timer extension field.  */
#define TX_TIMER_INTERNAL_EXTENSION   VOID *tx_timer_internal_extension_ptr;

/* Interrupt lockout and restore.  All CSR access is done in assembly
   (tx_thread_interrupt_control.S), so no inline assembly appears in C code
   (MISRA C:2025 Directive 4.3).  */
UINT _tx_thread_interrupt_control(UINT new_posture);

#define TX_INTERRUPT_SAVE_AREA   UINT interrupt_save;
#define TX_DISABLE   interrupt_save =  _tx_thread_interrupt_control(TX_INT_DISABLE);
#define TX_RESTORE   (VOID) _tx_thread_interrupt_control(interrupt_save);
1
32-bit ULONG on a 64-bit CPUThreadX control blocks and queue message sizes assume it. Pointers that do not fit go into extension fields; a compile-time array-size check fails the build if VOID * is not 8 bytes.
2
Runtime proof tooThe bring-up image prints PASS ThreadX data model (LONG/ULONG 32-bit, LP64) (LA-REQ-001).
3
Suppressions name a deviationThe type names are fixed by tx_api.h, so Dir 4.6 is deviated once (DEV-003) and every location carries the ID. No anonymous suppressions.

Every interrupt enters here, with interrupts already off

ports/loongarch64/gnu/src/tx_thread_context_save.S
    .section .text.trap.port, "ax"
    .balign 4096
    .globl  _tx_thread_vector_entry
_tx_thread_vector_entry:
    /* SAVE0 preserves the interrupted stack pointer without clobbering a
       general register.  Hardware has already cleared CRMD.IE. */
    csrwr   $sp, TX_LA64_CSR_SAVE0
    csrrd   $sp, TX_LA64_CSR_SAVE0
    addi.d  $sp, $sp, -TX_LA64_CONTEXT_FRAME_SIZE

    st.d    $zero, $sp, 0
    tx_la64_save_gprs
    csrrd   $r12, TX_LA64_CSR_ERA
    st.d    $r12, $sp, TX_LA64_CONTEXT_ERA_OFFSET
    csrrd   $r12, TX_LA64_CSR_PRMD
    st.d    $r12, $sp, TX_LA64_CONTEXT_PRMD_OFFSET
    tx_la64_save_fprs
    li.w    $r12, TX_LA64_CONTEXT_INTERRUPT_TYPE
    st.d    $r12, $sp, 0

    csrrd   $r12, TX_LA64_CSR_ESTAT
    srli.d  $r13, $r12, 16
    andi    $r13, $r13, 0x3F            /* Ecode != 0: synchronous */
    bnez    $r13, _tx_thread_vector_fatal
    andi    $r13, $r12, 0x4             /* IS[2]: external I/O     */
    bnez    $r13, _tx_thread_vector_external
    andi    $r13, $r12, 0x800           /* IS[11]: timer           */
    beqz    $r13, _tx_thread_vector_fatal

    bl      bsp_timer_ack
    bl      _tx_thread_context_save
    bl      _tx_timer_interrupt
    b       _tx_thread_context_restore
1
4 KiB-aligned entryEENTRY needs page alignment; the section is placed by the linker script and installed by _tx_initialize_low_level.
2
No free register on entryThe csrwr/csrrd pair through SAVE0 keeps the interrupted $sp while the frame is carved out.
3
Whitelist decodingOnly Ecode 0 with IS[2] or IS[11] is serviced. Anything else, including an unexpected interrupt line, goes to the fatal handler (LA-REQ-106).
4
No nestingIE stays clear until ertn, so stack depth is bounded and analysable (LA-REQ-009).

Why the low-level assembly is the safety-critical part

ports/loongarch64/gnu/src/tx_thread_interrupt_control.S
/* Sets CRMD.IE to the requested posture and returns the previous
   posture.  csrxchg reads and writes CRMD in one instruction, so the
   operation cannot be split by an interrupt.  (LA-REQ-002) */
_tx_thread_interrupt_control:
    li.w    $t0, TX_LA64_CRMD_IE
    and     $a0, $a0, $t0
    csrxchg $a0, $t0, TX_LA64_CSR_CRMD
    and     $a0, $a0, $t0
    jr      $ra
ports/loongarch64/gnu/src/tx_thread_system_return.S
_tx_thread_system_return:
    /* Record the caller's posture for the solicited return, then lock
       out interrupts before any bookkeeping: an interrupt taken after
       the switch to the system stack below, while
       _tx_thread_current_ptr still names this thread, would save a
       system-stack frame as the thread's context (PR-M5-001).  */
    csrrd   $r15, TX_LA64_CSR_CRMD
    andi    $r15, $r15, 0x7
    move    $r12, $zero
    li.w    $r13, TX_LA64_CRMD_IE
    csrxchg $r12, $r13, TX_LA64_CSR_CRMD

    addi.d  $sp, $sp, -TX_LA64_SOLICITED_FRAME_SIZE
    st.d    $ra, $sp, 8
    st.d    $r22, $sp, 24     /* ... $r31, $f24 .. $f31, FCSR0 */
C cannot express it. Which registers survive, when IE is clear, which stack is live, and the order of three stores decide whether a thread ever runs again. No compiler, MISRA checker or coverage tool sees those properties.
So assembly gets its own controls: requirement IDs in every file header, compile-time offset checks against the real TX_THREAD, requirement-based tests on QEMU, 600-run parallel stress, and review against the design (IEC 61508-3 7.4.4, Dir 4.2 and 4.3).
Problem reports PR-M4-001 and PR-M5-001  |  found by tests, fixed in assembly

Two real port defects the process caught

PR-M4-001: system stack leak in the idle loop

Symptom: 5 of 96 regression tests passed, then hung in cleanup.
Cause: a tick taken while the scheduler sat in idle 0 built a 608-byte frame on the system stack that was never released. About 26 idle ticks overflowed the 16 KiB stack into .bss.
Fix: when no thread was interrupted, restart on _tx_thread_system_stack_ptr (upstream RISC-V behaviour). Follow-up: a 256-byte guard with pattern 0x5AA5... and a long-idle test.

PR-M5-001: thread context captured on the system stack

Symptom: rare timeouts; 600 runs of one test, 24 QEMU instances in parallel: 231 hung (369/600).
Cause: _tx_thread_system_return assumed IE was clear, but tx_thread_relinquish calls it with interrupts on. A tick between the stack switch and the scheduler saved a system-stack frame as the thread's context.
Fix: lock interrupts with csrxchg before any stack change; the posture is saved in the frame. Stress: 600/600.
Verified== stress: threadx_thread_wait_abort_and_isr_test x 600, 24 parallel QEMU # from regression.md before fix passed 369/600 hung 231 after fix passed 600/600 == bringup_relinquish_interrupts_enabled Passed # the regression test added for PR-M5-001

bool bsp_external_irq_init(void) /* parasoft-suppress MISRAC2025-RULE_8_7-a "DEV-011" */
{
    uint32_t extioi_base = (uint32_t) BSP_EXTIOI_IOCSR_BASE;
    bool     ok = true;

    /* PCH-PIC: send line 2 out on vector 2.  The vector table resets to
       zero, which would route every line to EXTIOI input 0.  */
    *pch_pic_reg8((uint32_t) BSP_PCH_PIC_REG_HTMSI_VEC + BSP_UART_PCH_IRQ) =
        (uint8_t) BSP_UART_PCH_IRQ;

    /* EXTIOI: input group 0 to IP0, UART input 2 to CPU 0.  */
    bsp_iocsr_write32(extioi_base + (uint32_t) BSP_EXTIOI_REG_IPMAP,
                      (uint32_t) EXTIOI_IPMAP_GROUP0_IP0);
    /* ... enable input 2, unmask PCH-PIC line 2 ... */

    /* Verify the route as the guest observes it.  */
    if (bsp_iocsr_read32(extioi_base + (uint32_t) BSP_EXTIOI_REG_IPMAP) !=
        (uint32_t) EXTIOI_IPMAP_GROUP0_IP0)
    {
        ok = false;
    }
    return ok;
}

void bsp_external_irq_handler(void)
{
    /* End of interrupt at the EXTIOI first.  The UART line is level
       triggered but the EXTIOI latches, so clearing the service latch
       before draining guarantees that a byte arriving afterwards raises
       the CPU line again instead of being lost.  */
    bsp_iocsr_write32((uint32_t) BSP_EXTIOI_IOCSR_BASE + (uint32_t) BSP_EXTIOI_REG_COREISR,
                      (uint32_t) PCH_PIC_UART_IRQ_MASK);
    received = bsp_uart_rx_isr();      /* drain FIFO into a 128-byte SPSC ring */
}

Latch before drainA lost-byte race closed by ordering, not by timing. Overflow and line errors are counted, never blocking.

MISRA C:2025 as an enforceable contract, not a checklist

MISRA C:2025 is the current edition of the MISRA C guidelines: it consolidates MISRA C:2012 with its amendments and corrigenda and continues the C99/C11/C18 coverage. We build ISO C99, freestanding.

MISRA Compliance:2020 defines how to claim compliance: a GEP (enforcement plan), a GRP (re-categorization) and a GCS (compliance summary per guideline), plus deviation records.

Record DEV-001  |  Rule 5.10, Required

Anatomy of a Required deviation

ports/loongarch64/gnu/libc/src/tx_la64_string.c
void *memmove(void *dest, const void *src, size_t n) /* parasoft-suppress MISRAC2025-RULE_5_10-b "DEV-001" */
{
    uint8_t       *d = (uint8_t *) dest;       /* parasoft-suppress MISRAC2025-RULE_11_5-b "DEV-009" */
    const uint8_t *s = (const uint8_t *) src;  /* parasoft-suppress MISRAC2025-RULE_11_5-b "DEV-009" */
    size_t         i;

    if ((uintptr_t) d <= (uintptr_t) s)
    {
        for (i = 0U; i < n; i++)
        {
            d[i] = s[i];
        }
    }
    else
    {
        for (i = n; i > 0U; i--)
        {
            d[i - 1U] = s[i - 1U];
        }
    }

    return dest;
}
Why the names cannot change: GCC emits calls to memcpy/memset for struct copies and initialisers even with -ffreestanding, and ThreadX calls them. Without -nostdlib libc there is no other definition.
Hazard: a reserved name clashing with a library definition with different semantics. Why it cannot occur: no C library is linked, enforced in CI by nm -u on the object (no undefined symbols).
Evidence: unit test bringup_memory_functions covers overlap in both directions and zero length; 100% line coverage of the file.

What four days did not, and could not, produce

Human approvals. Deviation records and documents need the technical lead and the safety manager; DEV-001 has a conditional safety-manager approval, the rest are drafts. Approvals will be confirmed by signed git tags.
Independent reviews. Code, design and assembly reviews by an independent reviewer: logged as "not performed", never back-filled.
Full structural coverage. Statement, branch and MC/DC reports, plus fault injection for defensive paths.
Real silicon. Everything ran on QEMU 8.2.2. A 3A5000/2K-series board, its interrupt controller and timing need their own validation and a ROM-capable BSP.
Assessment. No independent assessor has seen this. It is an evidence package, not a certificate.
